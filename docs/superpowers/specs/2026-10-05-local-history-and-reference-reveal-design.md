# 本机历史会话与参考答案确认展示设计

## 目标与用户体验

六级助手左侧增加统一的本机历史入口：可新建对话、打开旧对话，也可打开过去的作文或翻译练习。用户从旧对话某一轮继续时创建新分支，原对话和学习记录均不删。作文/翻译练习的题目、学生原稿、AI 参考评语和修改稿在主区域按时间展示，页面底部不再重复堆放全部历史原稿。

作文/翻译练习与历史视图里的系统参考范文、参考译文及解析默认隐藏。用户主动点“查看参考答案与解析”，再点“确认查看”后才展示；取消则保持隐藏。不要求先交稿。参考内容标明“练习参考，非官方答案”。本次不制作作文范文；无已核实缓存时明确显示不可用。

## 已有边界

- `streamlit_app.py` 的聊天消息只在 `st.session_state`；刷新后消息和当前题目定位会丢失。
- `memory/episode.py` 只记录诊断轨迹，不保存完整助手回复，不能反向拼出旧聊天。
- `memory/learning_record.py` 已持久保存作文/翻译原稿、修改关系和评语；`Service.draft_history()` 能读回它们，不应迁移或复制学生原稿。
- 38 套 `parsed_papers/*.json` 当前均无 `writing_sample`、`writing_analysis`。已有的 [作文缓存设计](2026-10-03-cet6-writing-cache-design.md) 是内容制作规则，不是已完成的数据。

## 方案选择

1. **推荐：对话另存、本机历史合并展示。** 新聊天存到学习档案同级的 `chats/` 目录；旧原稿继续从现有学习事件读取。侧栏只合并两个来源的导航项，不把同一篇原稿复制进聊天库。改动与现有数据边界一致。
2. 把全部学习事件迁移到新聊天数据库：界面模型较统一，但旧稿迁移、去重和回滚语义复杂，容易把“学习事实”误当“聊天消息”；不采用。
3. 复用 `episodes/` 作为聊天历史：缺助手回复且日志主要用于诊断；不采用。

聊天档案使用标准库 JSON，每个会话一个文件；单机单进程写入时用临时文件加原子替换。目录从现有 `LearningRecord.path.parent` 派生，沿用 `EXAM_TUTOR_LEARNING_PATH` 的本机位置选择，不新增账号、云端同步或数据库依赖。若保存失败，本轮回复仍可显示，但页面明确提示“本轮对话未存档”；不宣称刷新后可恢复。

## 会话契约与回到旧节点

每个聊天文件保存 `id`、标题、创建/更新时间、可选父会话与分叉轮次，以及按顺序排列的完整轮次。标题在首轮完成时取用户原话去首尾空白后的前 30 字；新建空会话用“新对话”，本版不提供重命名。每轮保存用户原话、助手回复、完成后的题目定位快照。只保存已完成的轮次；不靠重放模型调用恢复状态。侧栏本版读取逐会话 JSON 后提取元数据；历史很多时列表可能变慢，待实际出现性能问题再建索引。

- “开启新对话”生成新会话和空题目定位。
- 点左侧旧会话时读回消息，用最后一轮的已验证定位快照重建 `Service` 的 `LocationTable`，使“为什么不选 A”类追问仍指向原题。
- 点某轮“从这里继续”时复制该轮及之前的轮次到**新会话**，保存父会话 ID/分叉点，恢复该轮定位；旧会话完全不变。分叉是新对话，不是撤销学习事件。
- 同一旧会话若在另一标签页已有新轮次，当前页提交时提示先刷新或从现有轮次分叉，不静默覆盖。
- 上线前未存档的旧聊天无法完整找回；不能从诊断日志伪造助手回复。已有旧原稿不受此限制。

会话文件只接受应用生成的安全 ID，读回时验证结构、角色、定位字段类型和长度；恢复定位只接受 `memory.session.FIELDS` 内的合法非空字段。坏文件跳过并提示，不自动删除。聊天档案与学习档案是两个独立数据源；删除或回到旧聊天不改判分、原稿和评语。

## 历史原稿的统一入口

侧栏按最近活动列出聊天与练习，条目注明“对话 / 作文 / 翻译”。旧原稿按 `revision_of` 链分组：只有明确的修改稿才属于同一次练习；即使同年同月同套，两篇独立初稿也不能强行合并为“第 1/2 版”。每篇原稿必须恰好出现在一个分组；若父稿失联或跨卷，该稿独立成组并提示，不能因分组而消失。点练习条目后，主区域显示题目、各版原稿及对应评语；“基于这版修改”回到既有提交路径，生成新版本，不覆盖旧稿。移除原页面的长“历史原稿与评语”展开区。

打开练习记录不自动读取参考内容。参考答案与解析在确认后从对应试卷缓存按年、月、套、板块读取，不复制进学习档案；比较缓存题目与存档题目时只折叠空白并去首尾空白，其他内容不做模糊匹配。若仍不一致或缓存待核，则不展示，说明原因。旧稿的题目一致性只影响该旧稿视图；聊天没有旧稿目标，不据此阻断用户明确索取当前试卷的已核实译文。

## 参考答案的确认门槛和内容来源

作文/翻译练习页与历史练习页共用三态流程：`隐藏 → 请求确认 → 本次查看已确认`。未确认时，学生视图与会话状态均不包含参考正文；首次仅在确认按钮的分支读取参考内容，此后的 Streamlit 重跑可按已确认目标重新读取，但会话状态只存目标与确认状态，不存正文。切换练习、切换会话或刷新后恢复隐藏状态。确认不是权限控制：本机文件的所有者仍可直接打开缓存。

翻译沿用已审核的 `translation_sample`/`translation_analysis` 和 `translation_needs_review`，与现有聊天路径共用审核标记和样文存在性判定；逐句解析只在有解析缓存时展示。作文缓存的 `writing_needs_review` 缺失或不为 `false` 一律视为待核；未来只有审核标记明确为 `false`、范文及中文解析非空且题目对应时才可展示。本次不修改 38 套题库，也不批量补写审核标记：现有作文均提示“暂无已核实参考范文”，绝不临时调用模型生成一篇冒充已收录答案。逐套核实原题要求、指定开头、字数与图表数据并撰写范文/解析，是独立的内容任务。

底部聊天中，用户明确问“翻译怎么写/翻译解析”等才展示现有已核实参考内容；既可一次写清年份、月份、套数，也可在已恢复且无歧义的会话定位上短追问。打开历史会话本身不自动发出参考内容。本设计的二次确认门槛仅针对作文/翻译练习和历史视图；未来若要对全部聊天索取答案也加同样确认，需单独定义对话状态和测试。

## 不在本次范围

- 不建立账号、云同步或多人共享。
- 不删除、回滚或重算历史阅读作答、作文原稿和评语。
- 不根据阅读题的对错臆测错因；“通过聊天确认阅读薄弱点并长期保存”待另行确定记录契约。
- 不改现有确定性 KEYS 判分与阅读讲题链路。
- 不修改 `parsed_papers/`；作文范文内容任务开始前须先做完整可恢复备份，因为目前父 Git 仓库没有 `HEAD`，该目录也未被跟踪。

## 验收

1. 新对话、旧对话恢复、刷新后继续、从任意完整轮次分叉均可用；父会话和学习档案字节不因分叉而改变。
2. 恢复或分叉后短追问使用该轮保存的题目定位，不串到另一会话。
3. 现有旧稿在侧栏可见；独立初稿不误合并，`revision_of` 修改稿正确串联，悬空修改稿独立可见；原稿/评语不迁移、不丢失。
4. 确认前的页面、`session_state` 和安全练习接口不含参考正文；确认后只展示对应、已核实、标注非官方的缓存内容；取消、切换、刷新均重新隐藏。
5. 缺失/待核作文缓存明确降级，现有 38 套题库不被本次任务改写；将来某套提供已审核的范文及中文解析后，无须改界面即可按同一门槛展示。
6. 运行 Streamlit 页面测试、聊天状态/定位测试、原稿存档测试、参考内容门槛测试及全量回归；测试使用临时聊天目录和临时学习档案，并对真实学习档案与聊天目录做测试前后哈希检查，不写入或改动真实本机记录。
