# CET-6 本机学习记录与主观题评阅设计

## 目标与适用范围

把现有阅读逐题练习扩展为覆盖阅读、作文、翻译的本机学习助手。学生可以逐题提交阅读选项，也可以在页面里输入自己的英文作文或译文。重新打开 Streamlit 或通过未来的 Codex Skill 使用时，同一操作系统账户能找回自己的提交、反馈和一项可执行的下一步。这里的“本机”指历史记录保存在本机；作文和翻译评阅需要把本次文本发送给 DeepSeek，并非离线评阅。

本设计只覆盖学习记录内核、主观题提交与反馈、Streamlit 和未来 Skill 对同一服务的调用边界。Skill 打包、安装和题库分发另立后续任务。

## 已确认的产品边界

- 不绑定 Codex 或 ChatGPT 账户，不做登录、云同步、跨设备恢复或多人共用一个系统账户下的档案。
- 只有学生**明确提交**才计为练习；查看范文、请求解析、输入“我不会”和普通聊天均不计。阅读无效选项或无可信 KEYS 不计作答。
- 阅读的正误只由缓存 KEYS 判定；作文和翻译没有单一标准答案，模型反馈只是参考意见，不输出或累计“官方分数”“正确率”，也不把作文/翻译混入阅读正确率。
- 作文、翻译反馈重点检查语法、时态、用词和搭配、全文连贯通顺。作文另外检查切题与结构；翻译另外检查原文信息覆盖、误译和漏译。不能只因表达不同于缓存范文就判错。
- 代码负责读取历史、计算可验证的数量/阅读正确率、决定下一步；模型负责主观题评语和建议措辞，不得改写客观记录。
- 每次只给一项下一步。不生成日历、周计划、新题，也不把模型自述的错误标签当作已验证的长期薄弱点。
- 学习档案不写进 Git 仓库，不存 API Key、完整聊天记录或阅读标准答案。

## 现状与方案取舍

目前 `streamlit_app.py` 的“逐题练习”只收第 26–55 题的字母答案；`retrieval/practice.py` 已有阅读判分后的纯统计函数。翻译缓存有中文原文、非官方参考译文和逐句解析，但 `_translation_answer()` 只提供查看，没有学生译文提交。作文缓存有题目；作文范文/解析的接入另有未实施计划，当前 `Service` 仍将作文问答标为未上线。部分 `writing_directions` 被 OCR 污染，不能把缺失的考试要求交给模型猜。

采用**一个用户本地 JSONL 学习事件账本**，默认放在当前系统用户目录的 `.exam-tutor/learning_events.jsonl`；`EXAM_TUTOR_LEARNING_PATH` 可配置另一处可写的本机文件，服务构造参数再覆盖它以便测试。沿用现有阅读判分与统计；新增主观题提交和反馈事件，不另建数据库、不添加依赖。Streamlit 与未来 Skill 都只调用同一 Python 服务，不各自实现持久化或评阅规则。

不把项目根 `episodes/*.jsonl` 当长期档案：它混有问答和测试轨迹，缺少可信学习者归属，而且当前 `Episode.record()` 会吞掉写盘错误。旧轨迹不自动导入；启用新账本后产生的提交才进入档案。现有 `episodes` 仍供诊断使用。

## 三种练习流程

### 阅读：客观判分

沿用现有安全出题接口。学生明确提交单题字母后，服务从该卷 KEYS 判分，返回正误、标准答案与解析；只有成功判分才追加一条 `reading_attempt`。出题视图在提交前不能含答案，练习和提交不能改动聊天 `LocationTable`。

### 作文：学生原稿与修改

按年份、月份、套数从缓存展示已知的英文写作题目及可信考试要求；使用原生多行输入框和显式“提交作文”按钮。现有 38 套缓存中 26 套无 `writing_directions`，12 套有，其中部分缺数字或混入无关试题；只有方向文字明确通过白名单才用于任务合规评阅，其余只做语言评阅。3 套 chart/graph 题虽有图表标记，但没有可安全呈现的图表材料，也只做语言评阅。没有足够可信题目材料时，不让模型补造题干；图表或指定开头等必要材料缺失时，明确说明该套暂不能完整评阅。作文练习**不依赖范文已完成**：可先以可信题目评阅学生原稿。练习视图默认不展示范文；原有查范文入口若日后上线，仍由用户主动请求。

提交后先保存学生全文，再请求 DeepSeek 根据实际题目和原稿给出：整体判断（定性）、值得保留的表达、具体问题、修改建议及一项优先修改动作。问题按语法、时态、用词/搭配、连贯性整理；能定位到局部错误的条目须引用学生原文片段并给出建议改法和中文理由。切题/结构判断仅使用已核实的题目要求。学生可在同一题上“修改后再交”，每一版单独保存并关联上一版；不能覆盖原稿或把再次查看评语算作新练习。不默认生成整篇替写作文。

### 翻译：学生译文与修改

按同样卷级定位展示缓存中文原文，使用多行输入框提交英文译文。只允许原文已核实的卷进入练习；`translation_needs_review` 不为 `false` 时不把待核内容当正式练习。提交后先保存译文，再把中文原文和译文交给 DeepSeek。反馈除共同的语言四项外，还逐项指出有依据的漏译、误译、信息顺序或语义不通之处；英文表达不同于缓存参考译文不等于错误。已有译文的问题引用学生译文片段；漏译没有对应译文时引用被遗漏的中文片段，不伪造学生原句。允许修改后再次提交并保留版本。参考译文标为非官方，只在用户主动查看时展示。

## 反馈契约与信任边界

模型收到的是本次题目/中文原文、学生提交文本和严格的评阅要求；历史档案全文、账本路径与 API Key 不发给模型。学生文本即使写有“忽略规则”之类指令，也只作为待评阅内容。界面在提交前明确告知：文本会保存在本机，并在请求评阅时发送给 DeepSeek。

反馈以结构化字段返回：定性总评、优点、问题列表、当前最应修改的一点。局部问题至少含类别、原文摘录、建议改法、中文原因；服务校验摘录确实存在于学生提交文本，且足够长/为完整词组，不能让单个 `a` 或 `I` 偶然匹配过关；漏译项则校验所引中文确实在题目原文中，拒绝凭空引述。连贯性、切题或整体信息覆盖可作为整体判断，但必须说明具体依据，不伪装成逐字语法错误。模型没发现明显问题时应如实说明，不凑错误数。反馈始终标“AI 参考评语，非官方阅卷”，不报预测六级分数。

模型超时或整体反馈结构不合格时，原稿仍已保存，状态显示“评阅未完成”；用户可以对同一稿重试，不产生新的提交次数。待评状态由“有 `draft_submitted`、无有效 `feedback_ready`”推导，刷新后仍可重试，不额外写失败事件。局部问题若引用了原稿中不存在的文字，只丢弃该问题并提示评语可能不完整；“未发现明显语言问题”可以是有效反馈，不必为凑条目而拒绝。代码可提供字数等可计算事实，但不得在模型失败时编造语法结论。

## 数据契约与进度计算

账本采用追加事件而非原地改写：`reading_attempt`、`draft_submitted`、`feedback_ready`。公共字段为 `event_id`、带时区的 `ts`、`section`、卷级定位；阅读事件另有 `question_number`、提交字母及由 KEYS 得出的正误；主观题提交事件另有全文、当时展示的题目/原文快照、`draft_id`、同一次提交操作的 `submission_id`，以及修改时指向上一稿的 `revision_of`；反馈事件通过 `draft_id` 关联对应稿件，只保存评语和评阅状态，不包含官方分数。账本层在同一应用进程内串行化同一路径的去重：同一 `submission_id` 的重跑只采用一稿，真正的新修改版使用新值；每个稿件最多采用一条有效反馈。首版不承诺多进程同时写入的事务保证。账本不存阅读标准答案或开发者密钥。最近一次按有效事件的文件追加顺序决定，而非按可改动的时间戳排序。

服务端校验定位与文本类型，拒绝纯空白或超过 10,000 个字符的作文/译文；不把 Streamlit 控件约束当安全边界。先确认本地提交写入成功，再发送给模型；写入失败时不得说“已保存”，也不应自动继续一次会丢失原稿的评阅。反馈写入失败时展示本次评语并明确告知“评语未存档”。坏行跳过、保留其他有效行并显示可见警告，不自动覆盖或删除原文件。

统计函数仍只接收事件序列、不接收文件路径。阅读继续计算累计/最近正确率、26–35/36–40/41–45/46–50/51–55 分组和既有 0–2、3–7、8+ 节奏；新字段 `repetition_groups` 使用 `(year, month, exam_set, question_number)` 聚合历史错次，并以该题按追加顺序的最新结果判定是否仍需复盘。现有 `reading.repeated_misses: list[int]` 保持兼容，但不用于跨卷推荐。作文与翻译分别显示提交篇数、修改次数、最近一次反馈状态，不合成阅读正确率，也不从模型意见算“语法错误率”。

默认下一步只跟随**最近一次练习**，避免旧稿永远占据推荐位：若最近一次是有有效反馈且尚未修改的作文/译文，建议按其首项可执行问题修改；若最近稿件评阅失败，建议重试该稿评阅；若最近一次是答错且尚未纠正的阅读题，建议复盘它；其他情况建议做一项已收录练习。若缓存题目已失效，回退为选择另一套已收录题，不杜撰内容。学生明确指定要练的板块时优先遵循指定板块。学习建议可引用 AI 反馈，但必须标注来源，不能把主观评语包装成确定性统计。

## 隐私、异常与后续 Skill

- 本机档案包含学生作文和译文全文，存于当前操作系统用户目录；应用本身不加密、不跨设备同步。不同系统账户默认使用不同目录。界面说明保存位置及手动清理方式，不把它放进项目或 Skill 分发包。
- DeepSeek 不可用时：阅读照常判分；作文、译文原稿已保存但反馈待完成，不显示虚构评语。恢复后可手动重试。
- 未来 Skill 只调用服务的出题、提交、反馈、进度接口，不直接解析账本或绕过 KEYS；不能声称 Skill 指令本身可阻止宿主读取原始缓存。
- 用户目录若被宿主沙箱禁止写入，必须显式报告，并提示通过 `EXAM_TUTOR_LEARNING_PATH` 配置可写的本机 JSONL 文件；显式服务路径优先于该环境变量。不能静默改存项目目录后仍声称恢复的是同一档案。
- 不做账户绑定、自动上传、旧轨迹迁移和跨设备同步。未来要加这些能力时，重新设计身份、授权和隐私删除。

## 验收与回归

1. 阅读正确、错误和重复提交的持久化判分仍由 KEYS 决定；不同试卷同题号不混淆；重开后客观统计恢复。
2. 作文、翻译各提交一版及修改版，重开后能看到原稿、关联的反馈与版本顺序；查看范文/解析、“我不会”和普通聊天不增加练习次数。
3. 反馈覆盖语法、时态、用词/搭配、连贯性；作文额外检查切题/结构，翻译额外检查漏译/误译。模型引用不存在的原稿片段时不当作有效问题展示。
4. 模型不可用、返回无效结构、保存失败、坏行和待核题目均有清晰提示；模型失败不丢原稿，不产生虚假分数或“已保存”误报。
5. 提交前阅读不泄露 KEYS；翻译待核原文不开放提交；作文缺失必要题目材料时不猜题。三类练习不改动聊天定位状态。
6. Streamlit 使用显式提交控件展示三类练习和“本机累计”，说明作文/翻译会发给 DeepSeek；只替换练习区旧的“刷新后进度清零”提示，保留聊天短问法在刷新后需重新定位的说明。历史阅读可恢复判分/重练入口；此前仅保存在会话轨迹里的模型解析不假装持久化。运行现有全量测试与场景评测，原有问答及 A/B/C 阅读练习不回归。

## 实施顺序与非目标

先完成一个最小纵向切片：本地账本和阅读恢复 → 翻译输入/反馈/保存 → 作文可信题目输入/反馈/保存 → 三类进度与下一步 → Streamlit 场景评测。作文范文/解析缓存补全可并行作为独立内容任务，不阻塞以可信题目评阅原稿；不可信或材料不全的题先提示不可完整评阅。

本设计不包含 Codex Skill 打包、官方分数预测、自动生成整篇替写稿、模型生成的新真题、跨设备同步或从旧 `episodes` 自动迁移。
