# CET-6 单会话练习闭环设计

## 目标

在现有六级答疑工具旁新增一个明确的练习流程：系统展示不含答案的段落匹配题，学生通过界面提交答案，代码按缓存 KEYS 判分，并根据当前会话作答记录提供适量反馈。首版验证“作答 → 确定性判分 → 有依据的下一步”是否成立，不建设长期学习档案。

## 已确认的产品决策

- 学生先作答，再看到标准答案及解析。
- 首版只在当前 Streamlit 会话内有效；刷新或重新打开页面后本次进度不恢复。界面须明确提示这一点；不加 `learner_id`、跨会话查询或新数据库。
- 学习事件继续写入现有 `episodes/*.jsonl`；统计函数只接收作答事件序列，不接收文件路径。
- 练习答案通过显式 UI 控件提交，不从普通聊天文本猜测作答意图；不新增 `ANSWER_SUBMISSION` 意图。
- 首版逐题作答、逐题判分；不提供一次提交 10 题的整组模式。
- 学生在当前练习中表示“我不会”时，先给予鼓励并引导他选一个尝试；不泄露答案，也不把这句话记作一次作答。
- 判分、统计与阶段阈值由代码负责；代码把已判分结果、对应证据和当前会话统计交给 LLM，LLM 只组织解析与下一步建议。
- 少于 3 次作答：判分、解析、一条下一步建议，并明确说明记录不足。
- 3–7 次作答：给代码计算的当前会话薄弱点和下一步建议。
- 达到 8 次：给当前会话复盘摘要和下一步建议；不生成完整复习计划。
- 完整复习计划、跨会话累计、长期薄弱点、自然语言作答识别、练习推荐和 MCP 均不在首版范围。

## 首版范围假设

首个练习题型限定为段落匹配（36–45 题），答案选项使用 A–R。此选择用于控制首版的数据与界面复杂度，不表示现有系统只支持段落匹配；现有选词填空、仔细阅读、翻译及直接答疑路径均须保持可用。

练习入口使用独立、显式的 Streamlit 控件定位已缓存试卷与题目；现有聊天输入仍用于原有答疑。若用户希望首版练习支持多个题型，需在实施计划前重新确认范围。

## 用户流程

1. 用户在独立练习区选择已收录试卷及一道段落匹配题。
2. 系统只展示题干、必要原文和作答所需信息，不展示答案字母或答案段落标记。
3. 若用户表示“我不会”，系统先鼓励他尝试，保留当前题目并引导其使用 A–R 控件；该回合不判分、不增加作答次数。
4. 用户通过 A–R 控件提交一个答案，提交后立即判分。
5. 代码从缓存读取 KEYS 并判分；模型不参与答案比较，也不能提交或覆盖标准答案。
6. 系统记录独立的作答事件，显示正误、标准答案及对应解析。
7. 代码基于当前会话作答事件计算档位和统计，并把已判分反馈、提交后证据及统计摘要直接传给 LLM，生成该档位允许的解释与建议。记录不足时不虚构薄弱点。

同一题重新练习应作为新的作答事件记录，不覆盖既有事件。用户逐题作答；答完后可开始下一题。首版不暂存多题答案，也不做批量提交。普通问答路径不自动切换为练习，也不记录为作答。

## 答案与数据边界

- 新增面向练习的安全题目视图，只返回界面展示所需字段；不得返回原始缓存题目对象、答案字母或可反推出答案的内部字段。
- 判分函数接收题目定位与提交答案，内部读取 KEYS，返回标准化判分结果；调用者不能把模型生成的答案作为标准答案传入。
- 解析证据只在提交后生成。现有 `build_evidence()` 会将 KEYS 放入讲解证据，不得用于提交前的练习视图。
- 作答记录使用独立字段（例如 `attempt_answer`、`attempt_correct`），不得复用 `answer_mentioned` 或 `answer_agrees`。每条轨迹仍遵守固定 schema；不做旧 JSONL 的兼容迁移。
- 统计函数采用纯输入输出形式，例如 `summarize_attempts(events)`；文件读取留在会话/服务边界。
- 首版可统计总正确率、最近作答正确率、36–40 与 41–45 区间表现及重复错题。陷阱类型不进入统计，因为现有陷阱标签来自模型讲解文本，尚非可信结构化事实。
- `practice_question` 和 `submit_practice_answer` 均不得修改普通问答共用的 `LocationTable`；练完题后原有聊天追问仍须定位到原题。

## LLM 反馈边界

- 首版使用一次普通 LLM 调用生成练习解析和下一步建议；代码在调用前确定判分、阶段和统计，不让模型选择工具或决定事实。
- 模型不得写 KEYS、改判、读取提交前答案、修改作答事件或创建跨会话档案。界面独立展示代码判分和标准答案，模型文本不能覆盖这些字段。
- 模型调用异常或返回空文本时，仍显示代码判分结果，并由代码按当前档位选择固定的简短下一步提示；不得影响现有问答服务。
- DeepSeek function-calling 的最小探针作为独立实验保留，记录思考模式开/关下的可用性；实验结果不决定首版练习功能是否可交付。

## 兼容性与回归要求

练习作为独立路径加入，不改变当前普通问答的直接查答案及追问行为。现有四条用户可见路径必须回归通过：段落匹配、仔细阅读、选词填空、翻译。现有测试全量通过，并验证 Streamlit 会话内服务仍能正确记录练习事件。

## 评测

扩展 `tools/scenario_eval.py`，复用现有 harness；新增作答流程用例覆盖：

- 提交正确答案与错误答案，判分严格匹配 KEYS；
- 问句中提到选项字母不产生作答事件；
- 提交前练习视图不包含答案，提交后解析证据可包含答案；
- 0–2、3–7、8 次作答分别进入正确档位；
- 统计结果可由独立事件序列复算；
- LLM 调用异常或返回空文本时仍保留确定性判分结果；
- 原有问答场景不回归。

不得把首版称作“模型自主选择工具的 Agent”，也不得把单元测试通过率描述为模型路由准确率。

## 明确不做

跨会话进度、长期计划、个人身份与隐私管理、并发标签页同步、自然语言作答识别、多题型练习、10 题批量作答与提交、自动练习推荐、模型生成新题、MCP 服务及完整周计划。

## 验收标准

1. KEYS 是唯一判分依据，正确与错误样例均有自动化断言。
2. 普通提问中的字母不会污染作答历史；作答字段与问答字段语义分离。
3. 练习题展示接口不含答案；答案只在提交之后进入判分/解析链路。
4. 三级门槛由代码决定，8 次及以上仅生成单会话复盘，不越界生成完整计划。
5. 作答事件可写入并从本会话轨迹还原，统计 API 只接收事件序列。
6. 新场景加入现有评测 harness，且所有既有问答路径与测试通过。
7. 练习出题和提交均不改变普通问答的定位表；界面提示本次练习进度刷新后不恢复。

## 待用户审阅的假设

首版只覆盖段落匹配题，并在练习区显式选择试卷与题目。若这不符合预期，应先调整本设计，再进入施工计划。
