# Findings

- Existing `tools/scenario_eval.py` tests Service state-machine scenarios, not Skill invocation.
- Existing `tests/test_cet6_skill_cli.py` covers several CLI contracts, including no-leakage and archive status.
- Official OpenAI guidance recommends prompt → captured `codex exec --json` trace → deterministic checks, including explicit, implicit, and negative-trigger cases.
- First live task-only trace passed after refining tool-failure scoring; a failed `.venv` probe was not a failed Skill command.
- Sandbox CLI had no auth, while the approved unsandboxed CLI was logged in. The first sandbox attempt timed out and was not scored.
- A live implicit reading case timed out after 180 seconds and produced no saved trace under the initial runner; timeout capture has since been added.
- Official OpenAI documentation recommends capturing structured `codex exec --json` traces and comparing tool steps; timeout output should not be conflated with a wrong answer.
- Direct cached-only Service Q48 answer took 3.37s in sandbox with DeepSeek `APIConnectionError` fallback, and 3.12s in networked execution with stage=`answer`; both returned cached `A`. Thus the 180s timeout is above the deterministic answer path.
- A completed Codex Q48 trace showed transport reconnects before tool use, then an unnecessary bare `python` attempt before project `.venv` was discovered. The project Skill now names its existing interpreter explicitly.
- The original evaluator's `subprocess.run(capture_output=True, timeout=180)` could remain blocked on Windows after the deadline when descendants retained captured pipes. The replacement writes events directly to a file and kills the process on timeout; a real timed child test verifies partial-trace retention.
- LangSmith tracing from the parent `.env` appeared in a live tool output despite parent process environment overrides. Official Codex configuration documents `shell_environment_policy.set`; the runner now passes temporary learning path and tracing flags explicitly through this setting. A post-change live Q48 trace completed without LangSmith error markers.
- Bounded live traces now pass for translation task, implicit Q48, and unrelated arithmetic (3/3 observed cases); the other nine cases have not been run. Codex transport retries remain external and sometimes consume most of the evaluation time.
- `tmp/` was not Git-ignored and may hold sensitive raw traces. The project `.gitignore` now ignores it. Full project verification finished at 193 passed with one existing `langchain-community` deprecation warning and no LangSmith post-test error.
- Completed all 12 isolated fresh-chat agent traces: 12/12 passed on saved-trace rescoring. The first `reading-why-not-b` attempt ended with `Selected model is at capacity` after the Skill command had succeeded; a bounded retry completed and passed. This was external interruption, not a wrong answer.
- The `reading-explicit` trace correctly replied `选 **E**`, but the evaluator initially rejected Markdown bold around the answer letter. A red/green regression test now covers this presentation form; the scorer normalizes Markdown emphasis only for its answer-pattern check. No tutoring behavior or cached answer changed.
- Manual final-message review confirmed the Q48 A-versus-B explanation uses the cached passage distinction (simulation itself versus what children learn), while missing coordinates and cache-miss paths do not invent an answer. The score still does not measure general explanation quality or writable multi-turn draft flows.
- A sandboxed full pytest run initially produced 22 temporary-directory cleanup `PermissionError` failures because Python selected a protected Windows sandbox Temp path. Re-running with `TEMP` and `TMP` set to the project-local `tmp` directory yielded 194 passed and one existing dependency deprecation warning.
- New scope approved: isolated writable multi-turn Skill evaluation for synthetic writing/translation drafts; do not change product grading or real archives.
- `codex exec --help` exposes `resume SESSION_ID [PROMPT]`; `--ephemeral` does not persist session files, so same-chat continuation needs a non-ephemeral initial run and a captured `thread.started.thread_id`. A separate fresh `codex exec` can test cross-chat archive recovery.
- CLI submission saves first, then reviews. `Service.review_draft` returns `pending` on model failure and `feedback_not_saved` on persistence failure; saved drafts remain retryable. `DEEPSEEK_API_KEY` is read from the environment; `load_dotenv()` does not override a present value, so an empty key may provide a bounded failure probe, but this needs empirical verification.
- `rg` against a nonexistent `writing` directory failed; reran against `retrieval/service.py` and `retrieval/draft_practice.py`. This was a search-path typo, not a project issue.
- First writable live flow saved an exact first draft, saved a revised draft with the correct `revision_of`, and completed fresh-chat history. The fresh-chat progress turn called `tools.cet6_skill progress` successfully (twice, including a UTF-8 retry), then Codex emitted `Selected model is at capacity` and `turn.failed`. This is an external final-response interruption; the scorer correctly reported `progress:incomplete_trace` instead of falsely passing.
- Isolated progress retry completed without resubmitting; final reply reported translation_count=2, translation_revisions=1, writing_count=0, and did not show draft text. Direct project CLI review of first draft succeeded outside Codex's workspace-write sandbox, isolating initial `APIConnectionError` to sandbox network access rather than a broken reviewer.
- Official Codex configuration reference documents `sandbox_workspace_write.network_access`; the evaluator enables it only for one opt-in synthetic retry-review turn, not globally or with `danger-full-access`. That real Skill retry called `review` without `submit`, saved feedback for the revised draft, and a subsequent fresh chat recovered both drafts and persisted feedback. Archive total: 2 draft events + 2 feedback events.
- Manual content check: first feedback identified `system are` → `system is` and substantial untranslated information. Revised feedback omitted the grammar issue but still flagged the omissions. The new-chat summary matched stored feedback; it was not asked to grade itself.
- Final fresh verification: 206 Python tests passed with one existing `langchain-community` deprecation warning; saved read-only Skill traces still score 12/12. The synthetic run archive has exactly two `draft_submitted` and two `feedback_ready` events; no temporary input file remained at project root. The writable scenario is one translation example, so no overall feedback-quality percentage or essay-writing claim is supported.
